06 Practice 2: Debugging Pong

This activity gives you more practice using pytest and the VS Code debugger to find logic errors. You will debug a small single-player Pong game written with Tkinter.

Starter Files

Open these two files in VS Code:

  • pong_game.py contains the game and its Tkinter window.
  • test_pong_game.py contains pytest tests for the game logic.

The game has a ball, a paddle, and a score. Use the left and right arrow keys to move the paddle. The tests call small functions from the game so you can investigate the logic without testing the Tkinter window directly.

Run the Program and Tests

Open a terminal in the lesson 6 directory and run the tests:

> python test_pong_game.py

If python is not the command on your computer, use python3 test_pong_game.py on macOS or Linux, or py test_pong_game.py on Windows. Read the pytest output and record the name of each failing test.

Run the game with:

> python pong_game.py

On macOS or Linux, you may need python3 pong_game.py. On Windows, you may need py pong_game.py. If the window does not appear, check that your Python installation includes Tkinter. When the window opens, press the Space bar or click in the window to start a round. After the ball reaches the bottom, press Space or click again to start another round.

Debugging Activity

There are four intentional bugs. Use the tests to learn which behavior is incorrect, then use the debugger to follow the values through the game. Fix each bug in the order below. Do not remove the tests.

1. Find a Score Rollover Bug

The score should increase by one each time the ball hits the paddle. When the score is 99, the next score should be 100. The failing test identifies the boundary case. Set a breakpoint in next_score, inspect the argument and return value, and step through the expression that calculates the new score.

Hint: Boundary values

Test the ordinary case and the boundary case separately. A calculation that works for 0 through 98 can still be wrong for 99.

2. Find a Paddle Collision Bug

The entire paddle should deflect the ball. The left-side collision test passes, but a ball aimed at the right side of the paddle does not deflect it. Set a breakpoint in ball_hits_paddle and inspect the horizontal and vertical overlap values. Step through the function with a ball position from the failing test.

Hint: Compare both sides

Compare the ball's right edge with the paddle's left edge, and the ball's left edge with the paddle's right edge. The collision should not depend on whether the ball is on the left or right half of the paddle.

3. Find an Early Wall-Collision Bug

The ball should deflect when it reaches the right edge of the screen, not before it gets there. Set a breakpoint in hits_right_wall. Inspect the ball's right edge and the screen width for a position one pixel before the edge and a position at the edge.

Hint: Use edges, not centers

The ball's position is its left edge. Add the ball size to find its right edge, then compare that edge with the screen boundary.

4. Find a Delayed Bottom-Wall Bug

The ball should speed up gradually but should never exceed the maximum speed. It should also leave the screen when it misses the paddle, no matter how many times the paddle has been hit. After five paddle hits, the bottom wall incorrectly begins deflecting the ball. Set a breakpoint in bottom_wall_deflects and use the Debug Console to call it with hit counts such as 0, 4, 5, and 10. Also inspect the value returned by ball_speed as the round continues.

After fixing the function, play a round long enough to make at least five paddle hits, then verify that a missed ball still ends the round. This is an example of a bug that appears only after a program has reached a particular state.

Hint: Follow the threshold

Calculate how many successful paddle hits are needed before the condition changes. The bottom wall should never become a deflector; a missed ball should end the round after any number of paddle hits.

Finish

Run test_pong_game.py again and confirm that every test passes. Run pong_game.py and verify that the paddle, ball, score, wall collisions, and speed all behave correctly.

Be prepared to explain which values you inspected in the debugger and how those values led you to each correction.
