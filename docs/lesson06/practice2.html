06 Practice 2: Debugging Pong

This activity gives you more practice using pytest and the VS Code debugger to find logic errors. You will debug a small single-player Pong game written with Tkinter.

Starter Files

Download and open pong_game.py in VS Code:

  • pong_game.py contains the game and its Tkinter window.

The game has a ball, a paddle, and a score. Use the left and right arrow keys to move the paddle. Hold an arrow key to move continuously; releasing it stops the paddle. The tests call small functions from the game, but you will download the test file after you have finished the debugging work.

Familiarize Yourself with the Code

Before looking for bugs, read through pong_game.py from top to bottom. Identify the constants, the small functions that calculate game behavior, the functions that set up the game, and the main function. Trace how a key press calls a function and how one call to update moves the game forward.

This program uses the Tkinter module to create a simple graphical window:

  • tk.Tk() creates the application window.
  • tk.Canvas provides the drawing area for the paddle, ball, score, and prompt.
  • bind connects keyboard and mouse events to functions such as press_left, release_left, and start_round.
  • after(16, update) schedules another update in about 16 milliseconds, creating the animation loop.

You do not need to learn all of Tkinter before starting. For this activity, focus on the values passed between the small game functions and the update function. The tests will check those small functions without opening a window.

Run the Program

Open a terminal in the lesson 6 directory and run the game: 

> python pong_game.py

On macOS or Linux, you may need python3 pong_game.py. On Windows, you may need py pong_game.py. If the window does not appear, check that your Python installation includes Tkinter. When the window opens, press the Space bar or click in the window to start a round. After the ball reaches the bottom, press Space or click again to start another round.

Debugging Activity

There are three intentional bugs. Use the game behavior and the debugger to investigate each one. You will download the tests after completing the debugging work to verify your corrections. Fix each bug in the order below.

1. Find a Paddle Collision Bug

The entire paddle should deflect the ball. The left-side collision test passes, but a ball aimed at the right side of the paddle does not deflect it. Set a breakpoint in ball_hits_paddle and inspect the horizontal and vertical overlap values. Step through the function with a ball position from the failing test.

Hint: Compare both sides

Compare the ball's right edge with the paddle's left edge, and the ball's left edge with the paddle's right edge. The collision should not depend on whether the ball is on the left or right half of the paddle.

2. Find a Speedup-Rate Bug

The ball should speed up slightly after it hits the paddle, but its speed should not change during an ordinary animation update. The starter code changes the speed even when the paddle was not hit. Set a breakpoint in update_speed and inspect current_speed, paddle_hit, and the returned value on several consecutive updates.

After fixing the function, run the game and observe that it begins at a manageable speed, speeds up after paddle hits, and does not become uncontrollably fast while the ball is traveling between hits.

Hint: Follow the event

Compare an update where paddle_hit is False with an update where it is True. The speedup rate should be applied only for the second case, and the result should never exceed MAX_SPEED.

3. Find a Round-State Bug

After fixing the speedup-rate bug, play long enough for the ball to gain speed. Let the ball miss the paddle, then press Space or click to start a second round. The second round should begin at the normal starting speed, but it begins at the previous round's speed instead. Set a breakpoint in start_round and step into reset_round_speed. Compare the value of current_speed with the value returned for a new round.

Hint: Reset all round state

List the values that change while a round is running. Check which of those values are reset when a new round begins. The ball position is reset, and reset_round_speed must return START_SPEED instead of reusing the previous speed.

Finish

Now download test_pong_game.py and save it in the same folder as your corrected pong_game.py. Run the downloaded test file one final time and confirm that every test passes:

> python test_pong_game.py

If python is not the command on your computer, use python3 test_pong_game.py on macOS or Linux, or py test_pong_game.py on Windows.

Then run pong_game.py and verify that the paddle, ball, score, wall collisions, round-start prompt, and speed all behave correctly.

Be prepared to explain which values you inspected in the debugger and how those values led you to each correction.
