06 Team Activity: Debugging a Hotdog Menu

Instructions

Work as a team as explained in the instructions for the lesson 2 team activity. Use the debugging techniques from the lesson 6 preparation material.

Purpose

Practice finding and correcting logic errors with three useful techniques: unit tests, print statements, and the VS Code debugger. A program can run without an error message and still contain an incorrect calculation, incorrect output, or an incorrect test.

The program in this activity prints a menu for a hotdog stand. It lists regular items, auxiliary items, and one discounted daily special. After you fix all three bugs, the output for day 1 should look like this:

Starter Files

Open these two files in VS Code:

  • hotdog_menu.py prints a hotdog menu and selects a daily special.
  • test_hotdog_menu.py contains pytest test functions for the menu program.

There are three intentional bugs. Fix them in the order shown below. Use the designated debugging technique for each one, even if you think you can spot the mistake by reading the code.

Debugging Activity

1. Find an Incorrect Test with pytest

Start by running the unit tests. In VS Code, choose Terminal > New Terminal. Change to the lesson 6 directory if necessary, and run:

> python test_hotdog_menu.py

On macOS, your command may be python3 test_hotdog_menu.py. On Windows, it may be py test_hotdog_menu.py. Read the pytest output carefully. It identifies the test function that failed and the line containing the failed assertion.

You can also run the tests from VS Code. Open test_hotdog_menu.py, then click the Run Test button shown above a test function or the Run Python File button in the upper-right corner of the editor. View the results in the Testing panel or the terminal.

Investigate the failing test_get_hotdogs test. A test has two parts: the actual value returned by the program and the expected value written in the test. Decide which one is wrong by comparing the test to get_hotdogs in hotdog_menu.py. Correct the test, not the menu data.

Hint: Reading pytest output

Look for the lines marked E in pytest's output. They show two values that are different. The failed-test heading tells you which test function to open.

Hint: Comparing expected and actual values

The variable returned from get_hotdogs is the actual value. The list on the right side of assert is the expected value. Compare each menu item and price in both locations until you find the disagreement.

Hint: What should change?

This activity contains a bad test, not bad menu data. Make the expected list in the test agree with the price defined in get_hotdogs.

2. Find an Off-by-One Error with Print Statements

Next, run the menu program:

> python hotdog_menu.py

The daily special is not the item that should be selected for the current day. Find today's day number, run the program, and compare the printed daily special with the reference table below. Use temporary print statements to trace the value of the day as it moves from main to display_menu and then to get_daily_special. Add a print statement immediately after the day is obtained and another before or inside the function that chooses the special. Include labels in your output so you know which value each line represents, for example:

print(f"day passed to display_menu: {day}")

Run the program after adding each print statement. Compare the values you see to the current day of the month. Then correct the calculation in main so it passes the intended day to display_menu. Remove your temporary print statements when you are finished.

Hint: Where to print

Start at the line in main that assigns a value to day. Then print the day parameter at the beginning of display_menu. If those two values agree, continue tracing it into get_daily_special.

Hint: Off-by-one errors

An off-by-one error occurs when a calculation is one value too high or too low. Check whether the value returned by datetime.now().day already represents the current day before it is passed to display_menu.

Hint: List indexes and calendar days

Python list indexes begin at zero, but calendar day numbers begin at one. Examine where the modulo operation is used and avoid changing more than the calculation that introduces the incorrect day value.

3. Find a Menu-Width Error with the Debugger

One line printed by display_menu is narrower than the rest of the menu. The unit test named test_display_menu_line_widths detects the problem. Leave that test in place and use the VS Code debugger to identify which printed line has the wrong width.

  1. Open hotdog_menu.py in VS Code.
  2. Click in the gutter to the left of a line in display_menu to set a red breakpoint. Begin near the first line that prints a separator.
  3. Open the Run and Debug view with Ctrl+Shift+D on Windows or Cmd+Shift+D on macOS. Choose Run and Debug, select Python if VS Code asks for a debugger, and press F5.
  4. When execution pauses, look in the Variables pane. Check the values of width and the expression used to create the line that is about to print.
  5. Use Step Over (F10) to execute one line at a time. Continue with F5 after examining a line. Use Step Into (F11) only when you need to enter a function such as format_menu_line.

As you step through the code, compare the requested width with the width passed to the line-formatting function. Correct only the statement responsible for the narrow line. Run the unit tests again to confirm that every menu line now has the requested width.

Hint: Choosing a breakpoint

The top and bottom borders use a different character at each end. The problem is in an interior separator line, so set a breakpoint on or just before the statements that print interior separators.

Hint: Inspecting values

While paused, hover over a variable in the editor or expand the Variables pane. You can also use the Debug Console to evaluate an expression such as len(formatted_line) after a line has been created.

Hint: What to compare

For an interior separator, compare both the number of separator characters and the width argument supplied to format_menu_line with the width variable in display_menu.

Finish and Pass Off

Run test_hotdog_menu.py one final time. All tests should pass. Also run hotdog_menu.py and verify that the menu borders and all interior lines have the same width.

Before you remove your work, show your corrected program and passing tests to the Teacher or TA. Be prepared to explain which tool you used for each bug and what evidence led you to the fix.
